# preview/menu_exact.html — пиксельная копия меню peekgg

Самодостаточный HTML (один файл, без сети и внешних ассетов), который рисует меню
`CPeekggGui` так, как его рисует C++ клиент. Нужен как база: показать текущий вид,
потом перерисовать под целевой скриншот и только после этого переносить вид в
`src/peekgg/theme.rs` + `widgets.rs` + `page.rs`.

## Файлы

| файл | что это |
| --- | --- |
| `menu_exact.html` | готовый деливерабл, ~230 КБ, шрифты вшиты base64 |
| `menu_exact.template.html` | исходник с плейсхолдерами `__ACTAY__` / `__ICONS__` |
| `peekgg-icons.otf` | Font Awesome Solid, подрезан до 7 иконок меню (4.5 КБ) |
| `build_menu_exact.py` | вшивает `data/peekgg/ActayWide-Bold.otf` и иконки в готовый файл |

Пересобрать после правки шаблона:

```
python3 preview/build_menu_exact.py
```

Шрифт берётся из распакованного C++ клиента: `/home/user/drive/so.loud/data/peekgg/ActayWide-Bold.otf`
(тот самый `SetCustomFace("Actay Wide Bold")`, 130 КБ, полная кириллица).

## Как устроены координаты

C++ считает всё в пикселях, умножая числа на `Scale`, где

```
ScaleBase = ScreenH / 600 * cl_peekgg_scale / 100
Pour      = 0.04 + 0.96 * OpenEase
Scale     = ScaleBase * Pour
```

HTML делает ровно то же: холст масштабируется на `Scale`, а все числа внутри —
те же константы, что в `peekgg_gui.cpp` (`46.0f * S`, `11.5f * S`, …).
То есть при `S = 1` код на canvas — построчный аналог C++, включая
`DoToggle / DoSlider / DoDropdown / DoStepper / DoColor / DoPick / DoRatio`,
`RenderCards` (жадная укладка по самой низкой колонке), `RenderSidebar`,
`RenderHeader`, `DoSearchBar`, выпадающий список, HSV-пикер, скроллбар,
подсказку в НАСТРОЙКАХ и перекрестие-курсор.

## Где расхождение (осознанное)

1. **Стекло.** В C++ это отдельный шейдер рефракции (`peekgg_glass_render`) поверх
   снятой сцены. В HTML — блюр сцены + тонировка `rgb(0.035,0.04,0.055)` и
   кромка white `0.10` (в C++ кромку рисует сам шейдер, отдельного контура нет).
   Геометрия островов, альфы затемнения и поведение — совпадают.
2. **Сглаживание кромок.** `DrawRoundedOutline` в C++ — текстура с готовым AA;
   в HTML — `stroke` с толщиной внутрь. Толщины и радиусы совпадают,
   микроразница на углах в 1 физпиксель.
3. **Текст.** Метрики canvas и `TextRender` движка чуть разные, поэтому обрезка
   длинных подписей («Прозрачность фо…») может срабатывать на другом символе.
   Шрифт — настоящий `ActayWide-Bold.otf`, размеры те же.
4. **Иконки.** Font Awesome подрезан до нужных 7 глифов; отрисовка центрируется
   по тем же правилам (`, `TEXTALIGN_MC`), но без `NO_Y_BEARING` флагов.
5. **Квирк исходника.** У `cl_peekgg_custom_aspect_ratio_mode` дефолт `-1`, а это
   вне диапазона дропдауна → в клиенте «Режим» показывает пустую строку.
   В копии стоит `0` («Выкл»), чтобы карточка не выглядела сломанной.

## Дев-панель (вне копии, клавиша `H`)

- `accent` — индекс палитры 0…12 (`cl_peekgg_accent`);
- `scale` — `cl_peekgg_scale` 70…130;
- `opacity` — `cl_peekgg_opacity` 0…100;
- `offline` — включает чип «Сервера» и мягкое затемнение `0.22`;
- `всё раскрыто` — разворачивает все карточки (по умолчанию свёрнуты, как в C++).

## Что делать дальше

1. Скриншот целевого меню → правим `theme.rs` (`MenuTheme`) под новые
   цвета/радиусы/шрифты и `widgets.rs` под новую форму контролов.
2. Правки вида сначала проверяются здесь (`menu_exact.template.html`), потом
   переносятся в Rust: один и тот же набор чисел.
